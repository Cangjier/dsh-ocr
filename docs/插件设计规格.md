# dsh-ocr 插件设计规格

**一句话**：把像素里的文字，变成带坐标的数据；把"按文字找位置"变成一次调用。

本文记录**取舍与实测**，不重复 README 的用法。每条结论都对应代码里的一个位置，或者一次真实的失败。

---

## 1. 边界：这个插件做什么，不做什么

| 做 | 不做 |
| --- | --- |
| 读出每一行的文字、置信度、像素框、中心点 | 判断这个读数够不够准 |
| 按字符串找到它的位置，给出可点击坐标 | 决定要不要点、点哪里 |
| 按 SRT 的时间点回读烧录字幕，逐条给相似度 | 判断字幕排版好不好看 |
| 装/查/卸离线引擎，sha256 硬校验 | 云端 OCR（视觉模型给不出逐行像素框） |
| 读视频帧（需 ffmpeg） | 描述画面内容（那是 `read_image` / 视觉模型的活） |
| WinRT 零安装回退 | 假装 WinRT 的读数和高精度引擎一样 |

**为什么不放在 video-factory**：那边是"素材进，成片出"。识别文字需要引擎、引擎安装路径、一套自己的坐标空间，还要能读视频帧——这些跟渲染一件都不相干。绑在一起的结果是：只想读一张截图，也要拖上整个视频工具链和几百 MB 的依赖。两边现在**互不依赖**：没装 `dsh-ocr`，video-factory 一切照常；没装 video-factory，`dsh-ocr` 照样读静态图（只有读视频帧和裁剪放大需要 ffmpeg，而它会自己去 `PATH` 和同目录找）。

## 2. 工具面：4 工具 / 11 action

散文只有一个来源：`src/tools/registry.mjs`。常驻 schema 与按需 guide 都从它派生，所以"schema 说的"和"guide 说的"不可能不一致——`tests/plugin.test.mjs` 会双向断言"注册了但没文档"和"文档了但没注册"。

| 工具 | action | 契约要点 |
| --- | --- | --- |
| `text_read` | `read` | `target` 或 `paths`（≤12）；`region` / `scale` / `engine` / `language` / `maxSideLen` / `minScore` / `frames` / `times` |
| | `verify` | `target` + `srt`；`sampleFrames`（默认 6）/ `leadSeconds`（0.35）/ `matchRatio`（0.6） |
| `text_find` | `find` | `target` + `needle`；`match: contains\|exact`；`minScore` **不生效**，所有行都搜 |
| `text_setup` | `status` `probe` `install` `remove` | 只读状态不启动引擎；安装按 sha256 硬校验；`prune` 省约 50 MB |
| `text_guide` | `overview` `tool` `action` `rules` | 全部派生自 registry 与安装器，不手写第二份 |

**为什么 `text_find` 是独立工具而不是 `text_read` 的一个 action**：两者在不同时刻被想起，意图也不同——"这张图写了什么" vs "写着这句话的东西在哪"。分开也让 `find` 的 schema 能把那件最要紧的事讲清楚：**没找到不等于不存在**，`searched` 才是区分依据。

**为什么 `verify` 在 `text_read` 里**：它和 `read` 回答的是同一类问题（像素上实际是什么），区别只在期望从哪来——`verify` 的期望来自 SRT。

## 3. 两个引擎，一套协议

两个引擎是独立程序，但形状相同：常驻子进程，stdin 一行 `{"image_path": "..."}`，stdout 一行一个 JSON 对象。所以一个客户端同时说两种话。

| 引擎 | 运行时 | 模型 | 本机实测（1200x1013 截图） | 平均置信度 | AVX |
| --- | --- | --- | --- | --- | --- |
| `rapidocr-json`（默认） | ONNX Runtime | PP-OCRv4 | **1.77 s** | 0.929 | 不需要 |
| `paddleocr-json` | Paddle Inference | PP-OCRv5 | 15.9 s（约 9 倍慢） | 0.833 | 要求 |

初始化：ONNX 0.33 s，Paddle 0.42 s。所以引擎是**常驻**的——第二次识别不再付模型加载的钱。

**为什么默认选慢的那半边**：它在同一张图上**既快 9 倍、分又更高**。Paddle 那条只在个别小字上更好（`gap` 没被读成 `qap`），为此付 9 倍时间不划算，所以它作为备选而不是默认。这些数字是测量值，不是估算。

**参数从真实文件拼出来，不从包的说明里抄**：RapidOCR 包自带的 `cmd.txt` 写的是 `ch_PP-OCRv4_rec_infer.onnx`，而它实际发的文件叫 `rec_ch_PP-OCRv4_infer.onnx`。照抄就是"引擎启动失败"。所以 `rapidArgs` 先枚举目录、按存在的文件名拼参数，缺什么就留给引擎默认值，**绝不下发一个不存在的路径**。

## 4. 坐标：唯一一条不能错的换算

引擎看到的往往是**裁剪并放大过**的图，调用者拿到的是**原图**的框。换算只有一条规则：

```
原图坐标 = 裁剪偏移 + 引擎坐标 / 放大倍数
```

顺序不能反：先除后加。反了就是"文字读得完全正确，点击落到别处"，而且误差随倍数呈平方级放大。

这条规则只在 `normaliseEngineResult` 一处实现（纯函数、无进程、无磁盘），单测从几个方向覆盖：旋转框、偏移 + 缩放组合、空文本行、低分行保留。

四点多边形**原样保留并换算**，不只是矩形：倾斜标签的包围盒会把点击放到偏的位置。

---

## 5. 归一化与匹配

`normaliseEngineResult` 产出的形状：

- `lines[]`：`{ text, score, box[4][2], x, y, width, height }`，按阅读顺序排序（先 y 后 x）。
- `text`：用 `\n` 连接**score ≥ minScore** 的行。
- `dropped`：被 `text` 排掉的行数。

**`lines` 永远不过滤**：0.4 分的行如果正好是你要找的那句话，它是命中不是噪声；静默丢掉它会让"没找到"变得无法解释。

`findLines` 的匹配只做两件事：转小写、去掉所有空白。去掉空白是因为引擎在 CJK 字之间插空格时有时无，`音 频` 必须能匹配 `音频`。除此之外不模糊——要更松的匹配，调用方拿 `lines` 自己后处理。

---

## 6. 预处理：小字必须先放大

`scale: "auto"` 的规则来自 RapidOCR 项目自己的做法（`limit_type: min`，`limit_side_len: 736`）：小图放大到长边约 1000px，**上限 3 倍**——再往上插值造出来的细节比它恢复的多。

实测：整屏 1.77 s / 35 行 → 只截一小块再放大 **0.16–0.2 s**。所以"给 `region`"既是精度建议也是成本建议。

裁剪与放大都交给 ffmpeg 一次做完（`crop=...,scale=iw*k:ih*k:flags=lanczos`），不引入任何图像库依赖。

---

## 7. 视频与字幕回读

**抽帧**：默认在整片**均匀**取 4 帧，不是从开头取——录屏开头常是标题卡。要给确切秒数就用 `times`，字幕回读走的就是这条路。

**字幕比对的两个关键决定**（都是实测逼出来的）：

1. **和"最好的一行"比，不和整帧比。** 教程视频里字幕背后常有一屏界面文字，拿整帧去比实测只得 0.03 分，而字幕其实完美可读——那量的是视频的其它内容，不是字幕。相邻两行**成对**也是候选，因为换行的字幕本来就分两行。
2. **比对前归一化**：全角转半角、去掉标点和空白，再按字符算最长公共子序列 / 较长者长度。OCR 读回的是**字形**，不是 SRT 里的逗号；要抓的失败是"缺字或错字"（`跑通你的第一个任务` vs `跑通你的第一个住所`），不是"换了一句话"。

**测不了就说测不了**：没有 SRT、SRT 解析不出条目、没有读取实现，都返回 `{skipped: 原因}`；引擎抛错返回 `{error}`。**空数组最像通过，也最容易骗过粗糙的调用方**，所以这两条路径必须与"通过"可区分。

## 8. 安装：钉死之后才解包

引擎不是能依赖的包，所以整套流程按"先钉死、再落盘"设计：

1. **归档钉 sha256。** release 资产不可变，所以清单里的哈希不符就是硬失败。一个被篡改或截断的下载，绝不允许成为"读你截图的那东西"。
2. **解包工具只记录、不强制。** `7zr.exe` 取自 `7-zip.org`，那个 URL 永远指向当前版本；强制哈希会让上游一发布新版安装器就彻底不能装——比"记录到一条哈希变化"更糟。所以不符时继续安装并把差异写进 `notes`。
3. **先解到 scratch，成功才移入。** 中断不会破坏已装好的树。
4. **状态从磁盘读，不读清单。** 清单说的是安装器**打算**装什么；可执行文件在不在，才是"能不能读字"的唯一依据。
5. **幂等。** 已装且能跑就返回 `installed: false`，不重复下载 73 MB。
6. **`archive` 用本地包，哈希照样校验。** 开发期间 GitHub CDN 把这次下载限到约 20 KB/s，70 MB 就是一小时。本地包这条路是刚需，但它**不等于不校验**。

**prune 的清单是白名单**：只保留简中识别模型、字典、共享检测器与方向分类器，删掉其余语言（约 50 MB）。白名单而不是黑名单，因为包里的文件名会随版本变。

---

## 9. 网络：自己读注册表代理

Node 的 `fetch` **既不读 Windows 注册表代理，也不认 `HTTPS_PROXY`**（Node 24 实测：设了变量、加了 `NODE_USE_ENV_PROXY=1`，仍然直连超时），而 `Invoke-WebRequest`、浏览器、其它 Windows 程序都走注册表。所以 `proxy.mjs` 自己读 `ProxyEnable` / `ProxyServer`，用 `http CONNECT` + `tls` 手写隧道——`undici` 在 Node 24 里不可导入，没有别的选择。

重定向必须自己跟：GitHub 的 `/releases/download/` 返回 302 跳 CDN，不跟就会把 200 字节的 "Found" 页面当成引擎包去校验哈希，而报错会指向"哈希不符"——一个完全错误的方向。

隧道用完必须释放：`response.once('end'|'close'|'error', () => agent?.close())`。留一个 keep-alive 的隧道 socket，表现为"命令干完活之后进程就是不退出"。

## 10. 进程与生命周期

- 会话按 `可执行文件 + 参数` 缓存，重复调用复用热进程（协议是"一问一答一行"，所以调用**串行化**：两次重叠的写会让回答分不清谁是谁）。
- 一次坏图不能让后续调用全部中毒：队列在失败后仍保持接通。
- 空闲 120 s 自动退出，释放约 500 MB；计时器 `unref()`，不拖住短命进程。
- 插件卸载时 `disposeOcrSessions()`。
- 启动等 `OCR init completed` 横幅；60 s 无消息即判失败，并把 stderr 尾部一起报出——引擎自己的抱怨才是有用的部分。
- 识别超时后**杀掉进程**再报错：卡住的引擎原地不可恢复，下次调用要干净地重来。

## 11. 文件布局与依赖

```
index.mjs              插件入口：apply / inject / 注册 / 配置校验
src/tools/             唯一知道 DSH 存在的层：registry + schema + action 实现
src/core/              确定性内核：纯 ESM、零第三方依赖、可离线单测
src/bin/ocr.mjs        CLI（同一批操作，便于调试与测试）
src/bin/ocr.ps1        WinRT 回退包装（PowerShell 5.1 不能直接 await WinRT）
vendor/ocr/            引擎（被 gitignore；钉死的 URL 与哈希在 core/install.mjs）
vendor/ffmpeg/         私有 ffmpeg（可选；通常借用同目录 video-factory 的那份）
```

**零第三方依赖**：`package.json` 没有 `dependencies`。这不是洁癖，是为了让"确定性"可离线证明——内核里每一个判断都能在没有任何模型、网络和 73 MB 下载的情况下跑测试。

## 12. 测试策略

68 个用例，分五层：

| 文件 | 层 | 说明 |
| --- | --- | --- |
| `tests/core.test.mjs` | 纯函数 | 坐标换算、匹配、region、放大、引擎参数拼装、`prune`、WinRT 参数 |
| `tests/subtitles.test.mjs` | 纯函数 + 注入 | SRT 宽容解析、归一化、相似度、抽帧选条、**"最好一行"而非整帧** |
| `tests/install.test.mjs` | 文件系统 | 二进制发现优先级、代理、sha256、**手工构造 zip 测解包器与路径逃逸** |
| `tests/plugin.test.mjs` | 契约 | 注册面与 registry 双向一致、schema 可序列化、跨工具不可达、guide 无空洞 |
| `tests/engine-backed.test.mjs` | 真引擎 | 小字中英混排读对、裁剪放大后坐标落回正确位置、视频逐帧、`find` 的 center 可用、`region` 不污染字幕回读、字幕回读端到端 |

**解包器不下载 194 MB 来测**：`install.test.mjs` 自己在内存里造 zip（stored 与 deflated 各一份），并造一个名字含 `../` 的恶意归档，断言它被拒绝。要防的失败必须能被证明，不能只写在注释里。

**需要引擎的用例干净跳过**，并在跳过信息里指出装引擎的 action。没装引擎不是构建失败，但**也绝不能伪装成通过**。

## 13. 已知限制

| 限制 | 说明 |
| --- | --- |
| 仅 Windows | 引擎是 Windows 可执行文件，零安装回退是 WinRT |
| WinRT 无置信度 | `score` 为 `null`，`minScore` 对它无效 |
| 不做云端 OCR | 视觉模型给不出逐行文字的像素框；要"看懂画面"用 `read_image` |
| 备选引擎许可未声明 | 商用前自行核对，见 README 的来源表 |
| 识别语言是每次调用的选择 | 多语种混排只有一份识别模型生效，混排小字可能低分 |
| 视频只在指定时刻取帧 | 0.4 秒的字幕用均匀取帧可能漏；知道时刻就给 `times` |
